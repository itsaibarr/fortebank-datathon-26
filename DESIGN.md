# Review workspace

The user-selected shadcn `b3d6mT4h6m` preset is the visual authority: Nova components,
zinc neutral surfaces, sky accent, Manrope body and Geist heading fonts, Lucide icons.
Keep its semantic tokens and component treatments. Fonts are local build assets;
runtime pages must not fetch third-party fonts or scripts.

The visitor is operating a review tool in a normal office. Use a light workspace,
legible neutral text, restrained boundaries and an accent for the current action.
Keep original footage the largest surface, a chronological event rail beside it,
and selected evidence and condition findings immediately below. On narrow screens,
stack video, events and details in reading order. No fabricated footage or findings.

Upload, processing, failed, completed and insufficient-evidence states must all be
explicit. The primary action is upload/analyze until a result exists; then selecting
an event seeks the video and reveals its evidence. Source timestamps use tabular
digits. Do not display model confidence as accuracy. Evidence and participant
overlays are distinct layers; source images remain available without overlays.

Use shadcn components for controls, fields, alerts, empty states, badges and tabs.
Keyboard focus, reduced motion and announced status changes are required. Browser
authentication uses a protected session cookie; keep only its CSRF token in component
memory. Service credentials stay on the server. Request resources through authenticated
same-origin fetch and object URLs; clear private state and revoke URLs when the session
ends or the principal changes. A reviewer correction shows its scope and saved
revision and does not change other review scopes. All browser QA uses synthetic data.
