---
title: "Technical limitations"
description: "What the implemented system and current evidence do not establish."
---

- Recognition and legal accuracy have not passed acceptance. Do not treat the demo, a `done` status, source integrity or a valid schema as semantic validation.
- Sparse sampling does not prove continuous visibility, an action's exact boundaries or an omitted mandatory step. Partial coverage is explicit.
- Participant IDs are recording-local proposals. Tracker associations, appearance features, reflections, geometry and roles have independent uncertainty and review scopes. No face identification is implemented.
- Three official acts and twelve draft interpretations are scoped legal resources. Historical edition, institution scope, unavailable cross-references and recording dates can prevent a legal conclusion.
- Stored human corrections preserve provenance but are not automatically replayed as later model context. Frozen weights are not trained or adapted.
- The local service admits at most two jobs and has one API process per filesystem root. One resident visual sequence is not a guaranteed two-job completion time.
- The selected real inference recipe requires a compatible Linux x86_64 CUDA host. Actual Laya CPU FP32 load, tokenizer compatibility, latency and RSS remain unverified. Visual CPU-only/offload inference and minimum RAM/disk capacity are not qualified.
- A clean new customer GPU installation, the exact new external browser/session boundary, broad end-to-end upload-to-UI latency and independent held-out quality remain separate acceptance tasks.
- The public Vercel site is a generated-data interface demo. It is not a real API or an accepted security boundary; direct `/api` and `/auth` network calls return 503.
- Originals, evidence, corrections and backups use manual retention. No automatic cleanup policy is promised.
- There is no audio analysis, identity lookup, hidden-accounting inference, multi-file batch API or arbitrary hosted model fallback.

See [verified measurements](/evaluation/results) and the [source evidence index](/guides/repository) before making a comparison or a release claim.


## Open source assessment limitations

Current condition packets are actor-wide. Unrelated ambiguity can suppress an
independently supported event, and collecting all packet evidence can exceed the
three-JPEG reporting budget. Event/condition scoping remains a source follow-up.
The v1 clearance replay also assumes one assessment per rule; multiple actor
assessments currently lead to conservative abstention. These are implementation
limitations, separate from unverified model accuracy and runtime performance.
