## Read metrics correctly

`forte evaluate` aggregates **v1** completed client result directories. It reports TP/TN/FP/FN, failed positives/negatives, completed fraction, accuracy including failures, effective recall, false-positive rate, supplied-point proximity and client median/p95/max. Missing or source-mismatched results are rejected. Failure is never converted to a negative.

- Accuracy including failures: `(TP + TN) / all planned known-label records`.
- Effective recall: `TP / all known positives`; failed positives reduce it.
- FPR: `FP / all known negatives`.
- Point proximity is a closest-timestamp diagnostic under eligible supplied points, not verified event matching or interval accuracy.

V2 abstentions must remain explicit in a separate protocol; feeding v2 rich JSON into the v1 evaluator is unsupported. A same-model v1/v2 run is not a model-size comparison. Ongoing evaluation is not included until its frozen results and provenance are verified.
