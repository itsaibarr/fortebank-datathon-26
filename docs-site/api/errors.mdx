---
title: "Errors and limits"
description: "Distinguish admission errors, processing failures and semantic abstentions."
---

| HTTP status | Actual meaning | Next action |
| --- | --- | --- |
| 202 | Job admitted. | Preserve its ID and poll the same version. |
| 401 | Required API key/session is absent or invalid. | Check the intended auth boundary. |
| 403 | Gateway Origin/CSRF or policy rejection. | Use the configured HTTPS origin and current CSRF token. |
| 404 | Unknown, cross-owner or ownerless job; unavailable resource. | Check version, ID and owner. Do not assume a job belongs to you. |
| 409 | Result not ready, source/evidence integrity failure, or correction conflict. | Read the specific error; refresh history for a correction conflict. |
| 413 | Multipart body exceeds the limit. | Use an input within 256 MiB including framing. |
| 415 | Unsupported/corrupt format. | Use a valid decodable MOV, not only a renamed extension. |
| 422 | Invalid fields, job identifier or unsupported video metadata. | Check `file`, UUID, video duration/dimensions and payload. |
| 429 | Admission/rate capacity is exhausted. | Wait; honor `Retry-After` where supplied. |
| 502 | Access component cannot safely verify/forward upstream. | Check the actual core/gateway connection and framing. |
| 503 | Model/configuration/access readiness unavailable. | Restore readiness; never substitute a cached clean result. |

Application errors use `error.code` and `error.message`; a failed job also has a terminal job ID and status. Model timeouts and insufficient evidence are not the same state. In v2, `done` with `insufficient_evidence` is explicitly reviewable abstention. In v1 reasoning projection it cannot be represented as a clean binary negative.

The Vercel demo's direct network `/api` and `/auth` paths return 503 because no inference/auth server is connected. Its labeled UI simulations happen in the browser and are not evidence of a deployed API.
